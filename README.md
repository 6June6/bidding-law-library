## 3. 文件格式

每份全文是带 YAML front matter 的 Markdown：

```yaml
---
编号: A02
名称: 中华人民共和国招标投标法
效力层级: 法律
分类: 交易程序
制定机关: 全国人民代表大会常务委员会
文号: —
公布日期: 2017-12-27      # 当前文本（含最近一次修正/修订）的公布日
施行日期: 2017-12-28
效力状态: 现行有效
沿革: 1999年8月30日通过，2000年1月1日施行；2017年12月27日修正…  # 首次公布与历次修订
原文地址: http://www.npc.gov.cn/…   # 官方原文页
抓取日期: 2026-10-28
---
```

正文保留原文条款结构，章/节转为 Markdown 标题，便于全文搜索与今后转换（PDF/Word 均可）。编码 UTF-8。

## 4. 检索方式

**日常检索**：打开 `index.html`（无外部依赖，拷到任何机器双击可用）。

### 搜得准

| 能力 | 说明 |
| --- | --- |
| **条文级定位** | 结果直接给出「第几条第几款」和命中片段，点击跳到正文并高亮——法律检索的价值是定位到条，不是只知道某篇文件里出现过 |
| **相关度排序** | 标题完全匹配 > 别名匹配 > 文号/机关/主题 > 条文正文，再叠 BM25 式的词频与逆文档频率；效力层级只做微调，不掩盖相关度 |
| **适用地区** | 新增维度。选中某省/市时，结果分「本地规定 / 全国规定」两段——**法律适用讲属地，两类都要看**；168 组同名异地条例（如 20 多个省的《建设工程勘察设计管理条例》）从此能分开 |
| **术语同义扩展** | 串通投标＝串标＝围标＝陪标；招标人＝采购人＝建设单位；工程总承包＝EPC…… 命中同义词算半权重，原词优先 |
| **条号直达** | 输 `第36条` 或 `第三十六条` 都能定位（汉字↔阿拉伯数字归一） |
| **查询语法** | 空格＝AND、`"串通投标"` 精确短语、`-政府采购` 排除 |
| **泛词不误伤** | 「项目」「范围」这类几乎篇篇都有的词自动降为加分项，不参与淘汰——否则 `必须招标 项目 范围` 会把全库算成部分命中 |
| **效力时点** | 施行日期晚于今天的标「待施行」，避免把尚未生效的规则当现行引用 |

### 搜得快

全文 223 万字拼成一个 blob 检索，一次线性扫描找完所有命中（V8 有 SIMD 优化），**实测平均 2.5 ms/次**；输入防抖 90 ms、结果缓存、列表 80 条起增量渲染。首屏把元数据与全文分成两个 `script` 标签注入，全文走 `textContent` 而不做 JSON 解析。

### 其他入口

- **表格筛选**：`catalog.csv` 在 Excel 中按层级/分类/**地区**/主题/日期排序筛选。
- **Markdown 导航**：`INDEX.md` 按效力层级、业务分类、**适用地区**三套目录组织。
- **文件级检索**：`grep -r "投标保证金" 0*/`，或把整个目录导入笔记软件。
- **分享检索结果**：`index.html#q=投标保证金`（加 `&d=序号` 可直接打开某篇）。

## 5. 更新方法

```bash
python3 tools/refresh.py            # 增量：重取元数据 → 补抓缺失全文 → 清洗 → 重建索引
python3 tools/refresh.py --full     # 全量：全部重抓（约 20 分钟，检索接口有限速）

# 扩充条目（三条采集通道）
python3 tools/harvest.py            # 先看候选（按主题词收割法规库）
python3 tools/harvest.py --commit   # 并入 items.json，再跑 flk_fetch 取全文
python3 tools/gz_harvest.py list "https://www.mohurd.gov.cn/gongkai/zhengce/gzk/index.html"
python3 tools/gz_harvest.py list "https://www.mohurd.gov.cn/gongkai/zc/xzgfxwjk/index.html" --strict
python3 tools/list_harvest.py "https://www.ndrc.gov.cn/xxgk/zcfb/fzggwl/index.html" --pages 10 --ling
python3 tools/gz_import.py data/gz_mohurd_gz.json --level 部门规章 --issuer 住房和城乡建设部

# 修文与校验
python3 tools/flk_fetch.py          # 从法规库补抓缺全文的条目（优先用它）
python3 tools/flk_fetch.py --force D08 D09      # 强制重抓指定条目
python3 tools/discover.py           # 法规库没有的条目（部门文件），走网页检索
python3 tools/compose_doc.py E09    # 正文在网页、标准在附件的文件合成
python3 tools/enrich_note.py        # 用题注刷新「沿革」字段
python3 tools/relink.py             # 多脚本并行后，按磁盘文件回填 file/src_url/chars
python3 tools/fetch_docs.py --reparse E05 E22   # 按已记录地址重新解析
python3 tools/sanitize_docs.py      # 体检存量正文噪声（预演，不落盘）
python3 tools/sanitize_docs.py --apply          # 落盘清洗
python3 tools/scan_noise.py         # 统计残留噪声，出 data/noise-report.txt
python3 tools/fix_header_block.py --apply  # 清「公文名称/索引号」块并回填文号、日期
python3 tools/fix_dates.py --apply         # 补齐空白公布/施行日期

# 检索维度与索引（改了正文或元数据后必跑）
python3 tools/fix_meta.py --apply          # 拆粘连 + 补日期 + 标待施行
python3 tools/normalize_meta.py --apply    # 地区/别名/机关归一/主题标签
python3 tools/build_index.py               # 重建检索索引
python3 tools/render.py                    # 重建 INDEX.md / index.html / catalog.csv
node tools/test_search.js                  # 检索回归测试（25 项断言）
```

`refresh.py` 的顺序：**法规库（flk_fetch）→ 网页检索（discover / fetch_docs）→ 附件合成（compose_doc）→ 沿革回填（enrich_note）→ 噪声清洗（sanitize_docs）→ 正文收尾（fix_meta）→ 维度派生（normalize_meta）→ 检索索引（build_index）→ 三件套（render）**。法规库有就用官方 docx（带题注、修订链条完整），没有再退回部委站点或网页。

> ⚠️ 并行注意：`flk_fetch.py` 与 `gz_import.py` 都会整表写回 `items.json`。两个同时跑会互相覆盖（本轮踩过一次，靠 `relink.py` 按磁盘文件回填救回）。要并行，先各自把新条目写进独立清单，串行入库。


`refresh.py` 的抓取顺序是 **法规库（flk_fetch）→ 网页检索（discover / fetch_docs）→ 附件合成（compose_doc）→ 沿革回填（enrich_note）→ 噪声清洗（sanitize_docs）→ 重建索引（render）**：法规库有就用官方 docx（带题注、修订链条完整），没有再退回网页。

**正文清洗口径**（`fetch_docs.sanitize`，抓取与存量清洗共用同一套规则，故两者结果一致）：

| 清理对象 | 处理方式 |
| --- | --- |
| 页脚：相关稿件链接 / 友情链接 / 主办单位 / ICP 备 / 网站标识码 / 国务院客户端 | 命中即丢该行；若页脚词前还粘着正文，只截掉后半段 |
| 编辑署名：「编 辑：××× 责 编：×××」「责任编辑：」 | 同上 |
| 导航链：「首页\|简\|繁」「登录个人中心」「_中国政府网」、含 2 个以上竖线的栏目串 | 整行丢弃 |
| 栏目字段壳：发文机关 / 索引号 / 主题分类 / 公文种类 / 成文日期 | 整行丢弃（信息已在 YAML 元数据里） |
| 落款粘连：「主 任 何立峰2018年3月27日<标题>」 | 拆成「主 任 何立峰」+「2018年3月27日」，尾巴的重复标题丢掉 |
| 转档残留：单独成行的页码（3、7、14） | 丢弃 |
| Word 域代码：`HYPERLINK "http://…"`、`PAGE \* MERGEFORMAT`、`javascript:SLC(…)` | 就地删除（条文中间的也删），顺带收紧书名号旁多余空格 |
| 重复正文块：PC 版 + 手机版渲染两遍 | 仅当重复块 ≥300 字且不含条文时去掉后一份 |
| 目录块：正文前的编/分编/章/节目录 | 与后文重名的目录行丢弃，正文标题保留 |

**安全底线**：条文行（`第X条`）与章/节标题在任何规则下都不删。清洗前后逐条比对条文数，414 件合计 14307 条一字未变。

**新增条目四条路子：**

1. 法律 / 行政法规 / 地方性法规 → 跑 `harvest.py`，主题词命中即自动收录（新增主题词改 `KEYWORDS`，口径改 `CORE/GENERIC/BAD`）
2. 部委规章 / 规范性文件（jpaas 平台）→ 跑 `gz_harvest.py list <栏目>` 采集清单，再 `gz_import.py <清单> --level ... --issuer ...`
3. 委办目录页（发改委等）→ 跑 `list_harvest.py <栏目> --ling`，白名单在 `data/list_*.json` 里改 `keep`
4. 单件补充 → 在 `data/extra.json` 里加一条（`level/title/doc_no/issuer/pub/eff/note/url`），跑 `refresh.py` 即抓正文

自动检索失败时，在 `data/manual_urls.json` 里手工指定官方原文地址（键为文件名，值为 URL），`discover.py` 会优先验证它。

**数据来源**：国家法律法规数据库（flk.npc.gov.cn）官方检索接口取法律、行政法规、地方性法规的权威元数据与**原文文件**（docx/pdf，含立法题注）；部门规章与国务院文件取中国政府网政策文件库；缺全文时依次回退到 gov.cn 公报/政策文件库、部委与省市人大政府官网。

## 6. 准确性与免责

- 全文均取自官方渠道，抓取时校验标题命中、条文数量与篇幅；老式 `.doc`、PDF 附件（如发改委规章）自动解析，硬折行自动合并。
- **正文只留法规本身**：页脚、友情链接、责任编辑署名、页面栏目字段、导航面包屑、重复渲染块已统一清掉（口径见 §5），每份文件从「# 标题」开始就是条文或题注。
- **引用请以官方发布文本为准**；本库仅供检索参考，不构成法律意见。
- **适用地区**由标题与制定机关自动抽取（省级 31 / 市级 36 / 州级 2，其余归全国），414 件逐条核对过，无错分。它决定「这份规定管不管我这个项目」——选了地区后结果是本地规定 + 全国规定两段，两者都适用。
- **主题标签**由标题强特征词确证、正文词频补充（阈值：强词 ≥3 次且弱词 ≥4 次），避免「监督管理」这类总则泛词把标签打花。
- 施行日期晚于今天的文件标「待施行」（当前 2 件：招标投标领域信用管理暂行办法、公共资源交易中心招标投标现场管理暂行办法，均 2027-01-01 施行），不要当作现行规则引用。
- 收录的是**最近一次修正/修订后的文本**，「沿革」字段直接取自原文题注（如「根据 2024 年 11 月 28 日……第三次修正」），可以据此判断手上版本是否最新。
- 「沿革」覆盖 276/414。有题注的（法律、行政法规、地方性法规、部委令）全部自动抽取；余下 138 件是通知类规范性文件——原件本身只有标题和正文，没有立法题注，其公布/施行日期由 YAML 元数据字段保证。

## 7. 已知局限

1. 部分「通知」类文件正文很短（仅数百字），实质规则在附件中；标准类附件已按 `data/attachments.json` 合成进正文（如评标专家专业分类标准），其余范本附件未逐一下载。
2. 少数文件的附件里有表格/清单被转成纯文本（如评标专家分类编码、中小企业声明函、GB 标准清单），内容保留了但丢失表格排版——检索可用，引用原表请以官方 PDF 为准。
3. **地方政府规章**（省市政府令）与县级规范性文件未收录——法规库不提供这一层级，需逐省市抓取；这是当前最大的空缺。
4. 适用地区按「标题前缀 → 制定机关」抽取，个别联合发文按主发机关归；若某件文件的属地判错，改 `normalize_meta.py` 的 `RE_TITLE_REGION` / `RE_ISSUER_REGION` 重跑即可。
5. 检索没有中文分词器，靠「整词子串 + 同义词扩展」工作。好处是零依赖、离线可跑；代价是长句式的自然语言提问（「招标失败后怎么办」）召回不佳——**用关键词检索，不要用问句**。
6. `catalog.csv` 中「文号」为「—」的，表示该层级惯例不编文号，或原件无文号、待核实。
7. 法规库改版过（旧 `/api/detail` 已下线），`flk_fetch.py` 依赖现行接口；若接口再变，改 `api_get` 的两个路径即可。

## 11. 接入 AI：用 MCP 让模型直接查库

**为什么不是直接把 414 篇扔给模型**：222 万字约合 150 万 token，超出绝大多数模型的上下文，
也不可能每次对话都全量塞进去。正确做法是让模型**先检索、再取证**——`tools/mcp_server.py`
把本库包成 MCP 服务，模型自己调工具取回命中的那几条条文，读到的是原文而不是记忆。

```
模型 ──search_law("投标保证金 上限")──▶ MCP 服务 ──▶ data/search-index.json + fulltext.txt
     ◀──《招标投标法实施条例》第二十六条 原文 ─────┘        （2.2MB 全文始终不进上下文）
```

### 四个工具

| 工具 | 作用 | 典型调用 |
| --- | --- | --- |
| `search_law` | 关键词检索，返回条级命中（法规名 + 条号 + 条文原文 + 层级/地区/日期） | `query="串通投标 认定"`、`region="安徽"`、`level="行政法规"` |
| `get_article` | 精确取某篇第 X 条，条号汉字/数字均可 | `doc="招标投标法实施条例", article="26"` |
| `get_document` | 取整篇正文（分页，默认 5000 字） | `doc="A01"`、`offset=5000` |
| `list_documents` | 按层级/地区/年份/关键词列条目，用于"库里有没有" | `level="法律"`、`year="2024"` |

检索在本地完成，只把命中的条文交给模型；每条结果都带**《法规名》第X条**的出处，
模型引用时可核对，也便于你在原文里复查。

### 配置（以 WorkBuddy / Claude Desktop 为例）

```json
{
  "mcpServers": {
    "legal-library": {
      "command": "python3",
      "args": ["/绝对路径/legal-library/tools/mcp_server.py"]
    }
  }
}
```

- WorkBuddy：写入 `~/.workbuddy/mcp.json`，然后在连接器页面点「信任」启用
- Claude Desktop：写入 `~/Library/Application Support/Claude/claude_desktop_config.json`
- Cursor：`~/.cursor/mcp.json`，配置格式相同

只依赖 Python 3.10+ 标准库，无需 pip 安装。首次使用前先跑一次
`python3 tools/build_index.py`（生成 `data/search-index.json` 与 `data/fulltext.txt`）。

### 可以这样问

- 「投标保证金最多能收多少？给出条文依据」→ 模型会检索并引《实施条例》第二十六条
- 「我们公司在合肥，围标怎么认定，安徽有没有更细的规定？」→ 带 `region=安徽` 检索，本地＋全国两份
- 「必须招标的项目范围是怎么规定的」→ 定位到《必须招标的工程项目规定》与范围规定
- 「帮我核对：招标文件发售期不得少于 5 日，对吗？」→ 取条文原文比对，而不是凭记忆点头

`gzip_static` 预压缩后 **1.8 MB / 约 2.2 秒**（未压缩是 7.8 MB / 10 秒）。

**`index.html` 是自包含的**，不依赖任何后端。数据更新后本地一条命令即可同步：

```bash
python3 tools/render.py          # 重新生成 index.html

```

服务器侧的执行者是 `tools/deploy-law-site.sh`（也可单独在服务器上以 root 跑，
参数给 `/tmp/index.html` 或某个 URL）：

```bash
bash deploy-law-site.sh /tmp/index.html
```

脚本做的事：校验文件完整 → 预压缩 `.gz` → 生成 `/etc/nginx/law-snippets/law.conf`
（`gzip_static` + 1 小时缓存 + `/law` 301）→ **找到真正 `listen 80` 的那个 server 块**
并插入一行 `include`（不会插到 443 块上）→ `nginx -t` 不通过自动从 `.bak-时间戳` 回滚 →
reload 后自检 `/law/` 内容与本机首页状态码。它只插一行 include，不动任何既有 location；
幂等，重复跑不会重复插入。

**SSH 连不上时先分清是哪一层的问题**（这次踩过）：

```bash
ping -c2 你的服务器IP                      # 通 → 主机在线
curl -o /dev/null -w '%{http_code}\n' http://你的服务器IP/   # 200 → 80 正常
nc -z -G 5 你的服务器IP 22                  # 超时 → 22 被挡
```

若 22 超时、80 正常，用第三方节点做对照（本机 IP 被封还是端口全局未开）：

```bash
curl -s -H "Accept: application/json" \
  "https://check-host.net/check-tcp?host=你的服务器IP:22&max_nodes=4"
# 拿 request_id 再查结果
```

- **全球节点全超时** → 云防火墙/安全组没放行 22，去控制台加规则（TCP:22，
  来源填当前公网 IP；家庭宽带是动态 IP，换网后要重加）
- **只有部分节点超时** → 服务器侧把该 IP 封了（云镜/fail2ban），走控制台 VNC 解封

腾讯云「云助手」可以在**不开 SSH** 的情况下以 root 执行脚本，安全组没放行 22 时
这是最快的通路：控制台 → 实例 → 云助手 → 发送命令 → 粘贴上面的 `bash` 命令。

## 13. 数据质量守则（踩过的坑）

1. **硬折行会毁掉检索**：docx 转换常保留「每 20 字断一行」，`维护公平竞\n\n争` 会让
   「公平竞争」永远搜不到。`tools/fix_wrap.py` 专门修这个，判据是「该文件里有词只有
   去掉换行才找得到」；修完必须满足**去掉所有空白后字符串完全不变**——只许移动空白，
   不许增删改字。表格/编码清单类文件整篇跳过，合并会破坏表结构。
2. **片段要取最相关的那一条**，不是"第一条命中的条"。搜「串通投标 认定」时正文里先
   出现的是「招标代理机构资格……认定」，按首次命中摘出来就是完全无关的第十一条。
3. **同义词不能倒挂**：把「保证金」当成「投标保证金」的等价词，会让《质量保证金管理
   办法》顶掉真正的答案。同义词只在原词没命中时给半权重。
4. **同条共现是强信号**：「投标保证金」和「不得超过」落在同一条里，比两个词分散在两
   个章节相关得多，值得单独加权。
